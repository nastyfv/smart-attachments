# SRS - Smart Attachments

**Версия:** 1.0
**Дата:** 02.11.2026
**Автор:** nastyfv
**Статус:** MVP реализован

---

## 1. Назначение

Smart Attachments - плагин для Obsidian, который автоматически создаёт и поддерживает заметку-каталог для каждого вложения в vault.

## 2. Проблема

В Obsidian вложения (PDF, изображения, документы) хранятся как «чёрный ящик»: нет единого каталога, нет метаданных, нет связей с заметками. При переименовании и удалении файлов связи теряются.

## 3. Цели

- Автоматически каталогизировать вложения с метаданными.
- Поддерживать актуальность каталога при изменении файлов.
- Сохранять историю (не терять заметки при удалении файлов).

## 4. Границы

**Входит в scope:**
- Создание заметки-каталога для файлов из папки вложений.
- Обновление содержимого заметки при переименовании файла.
- Пометка заметки как `orphan` при удалении файла.
- Ручная пересборка индекса.
- Удаление всех orphan-заметок одной командой.

**Не входит в scope:**
- Обратные ссылки из других заметок (v2).
- Работа с мобильным Obsidian (плагин только для desktop).
- Синхронизация между устройствами.
- Поиск по метаданным через UI.

## 5. Функциональные требования

### FR-01. Создание заметки-каталога
При появлении нового файла в папке `attachments` плагин должен автоматически создать Markdown-заметку в папке `catalog` с метаданными: путь, имя, расширение, размер, хеш, дата создания.

### FR-02. Обновление при переименовании
При переименовании файла в `attachments` плагин должен обновить в заметке путь, имя и заголовок. Имя самой заметки остаётся неизменным.

### FR-03. Пометка orphan при удалении
При удалении файла из `attachments` плагин должен обновить статус в заметке на `orphan` с указанием даты удаления. Заметка не удаляется.

### FR-04. Пересборка индекса
Пользователь должен иметь возможность запустить пересборку индекса вручную через палитру команд. При пересборке: создаются недостающие заметки, пропавшие файлы помечаются как `orphan`, выводится отчёт.

### FR-05. Удаление orphan-заметок
Пользователь должен иметь возможность одной командой удалить все заметки со статусом `orphan` из каталога и соответствующие записи из индекса.

### FR-06. Настройка папок
Пользователь должен иметь возможность указать папки для вложений и каталога в настройках плагина.

## 6. Нефункциональные требования

### NFR-01. Производительность
- Время реакции на создание файла: ≤ 1 секунда для файлов до 10 МБ.
- Пересборка индекса: до 10 000 файлов без деградации UI.

### NFR-02. Платформа
- Desktop: Windows, macOS, Linux.
- Mobile не поддерживается.
- Obsidian ≥ 1.4.0.

### NFR-03. Хранение данных
- Индекс хранится в `data.json` в папке плагина.
- Настройки хранятся там же.

### NFR-04. Совместимость
- Не конфликтует с другими плагинами.
- Не модифицирует файлы вне `attachments` и `catalog`.

### NFR-05. Безопасность
- Не передаёт данные наружу.
- Не выполняет сетевых запросов.

## 7. Ограничения

- Дубликаты по хешу не создают вторую заметку.
- При переименовании файла заметка не переименовывается (для сохранения обратных ссылок).
- Ручное удаление заметки не синхронизируется с индексом автоматически.
- Хеш считается для файла любого размера (может замедлить Obsidian на больших файлах).

## 11. Глоссарий

| Термин          | Значение                                                      |

| Vault           | Хранилище Obsidian (папка с заметками)                        |
| Вложение        | Файл в папке `attachments` (PDF, изображение, документ)       |
| Заметка-каталог | Markdown-заметка в папке `catalog`, описывающая одно вложение |
| Индекс          | Внутренняя структура плагина, хранящая сведения о вложениях   |
| Orphan          | Статус заметки, означающий, что соответствующий файл удалён   |
