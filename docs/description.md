# Smart Attachments — описание проекта

## Зачем этот проект

В Obsidian вложения - PDF, изображения, документы, архивы - живут отдельно от заметок. Они лежат в папке `attachments`, но у них нет ни описания, ни метаданных, ни связей с основной базой знаний. Со временем накапливается «чёрный ящик»: непонятно, что это за файл, когда он появился, используется ли он вообще.

**Smart Attachments** решает эту проблему: для каждого файла в папке вложений автоматически создаётся заметка-каталог с метаданными. Каталог поддерживается в актуальном состоянии при переименовании и удалении файлов.

Проект задуман как **пет-проект системного аналитика**: сначала требования, сценарии, модель данных и критерии приёмки, потом - реализация. Это не «плагин, который я написала за вечер», а полный цикл: от анализа до кода.

## Кому это нужно

- **Исследователям и аналитикам**, которые ведут базу знаний в Obsidian и хранят документы внутри vault.
- **Писателям и студентам**, у которых много PDF и картинок в заметках.
- **Всем, кто хочет**, чтобы вложения были частью базы знаний, а не «мусорной папкой».

## Что делает плагин

- **Создание.** При появлении файла в `attachments` автоматически создаёт заметку в `catalog` с метаданными: путь, имя, размер, тип, SHA-256 хеш, дата.
- **Переименование.** При переименовании файла обновляет путь, имя и заголовок в заметке. Имя самой заметки остаётся прежним - чтобы не ломать обратные ссылки.
- **Удаление.** При удалении файла помечает заметку как `orphan` с датой удаления. Заметка не удаляется - сохраняется история.
- **Rebuild index.** Команда для пересборки индекса: создаёт недостающие заметки, помечает пропавшие файлы как `orphan`, выводит отчёт.
- **Delete all orphan notes.** Команда для очистки каталога от заметок с удалёнными файлами.
- **Защита от дублей.** Если файл с тем же хешем уже есть в индексе, вторая заметка не создаётся.
- **Группировка по типу.** Заметки раскладываются по подпапкам: `images/`, `documents/`, `audio/`, `video/`, `archives/`, `other/`. Настройка отключается.
- **Теги по типу.** В каждой заметке автоматически ставятся теги: `#attachment` + `#image` / `#document` / `#audio` / `#video` / `#archive` / `#other`.

## Как устроено

Плагин написан на **TypeScript** и использует **Obsidian API**. Сборка - через **esbuild**.

### Архитектура

- **main.ts** - точка входа. Регистрирует обработчики событий (`create`, `rename`, `delete`) и команды.
- **Index (в памяти + `data.json`)** - структура, которая хранит все записи о вложениях. Ключ - путь к файлу, значение - запись `Attachment`.
- **Note (Markdown-файлы в `catalog/`)** - заметки-каталоги. Создаются по шаблону с YAML-фронтматтером.
- **Settings** - папки `attachments` и `catalog`, настройка `groupByType`. Хранятся в `data.json` рядом с индексом.

### Модель данных

Подробно - в [data-model.md](data-model.md). Кратко:

- `Attachment` - запись в индексе: путь, имя, размер, хеш, статус, даты.
- `Note` - Markdown-файл с фронтматтером, который **дублирует** метаданные для самодостаточности.
- `Settings` - singleton-объект с настройками.

### Ключевые решения

**1. Заметка не переименовывается при переименовании файла.**
Если переименовать и заметку, сломаются обратные ссылки `[[picture]]` из других заметок. Поэтому при переименовании файла обновляется **содержимое** заметки (путь, имя, заголовок), а имя `.md` остаётся прежним. Пользователь видит актуальные данные внутри, а сама заметка - стабильный якорь.

**2. При удалении файла - orphan, а не удаление заметки.**
Заметка сохраняется с пометкой `orphan` и датой удаления. Это позволяет:

- сохранить историю (что было удалено),
- не сломать ссылки из других заметок,
- защититься от случайного удаления.

Очистка - отдельной командой «Delete all orphan notes».

**3. Метаданные дублируются в индексе и в заметке.**
Это осознанное решение: если индекс (`data.json`) потеряется, данные останутся в заметках. Цена - дублирование, выгода - устойчивость.

**4. Хеш SHA-256 - для защиты от дублей.**
Если два файла с одинаковым содержимым попадают в `attachments`, создаётся только одна запись. Это защищает от случайного копирования.

**5. Группировка по типу - с миграцией.**
Если пользователь включил группировку после того, как уже накопил заметки в плоском каталоге, при запуске `Rebuild attachments index` они автоматически переезжают в нужные подпапки. Это делает фичу безопасной для существующих vault.

## Что работает и что нет

### Работает

- Создание заметки при появлении файла.
- Обновление содержимого при переименовании.
- Пометка `orphan` при удалении.
- Пересборка индекса.
- Удаление всех orphan-заметок.
- Защита от дублей по хешу.
- Настройка папок `attachments` и `catalog`.
- Группировка по типу файла с миграцией существующих заметок.
- Теги по типу файла.

### Известные ограничения

- **Ручное удаление заметки** из `catalog` не синхронизируется с индексом. В индексе останется «мёртвая» запись. Планируется команда «Cleanup index».
- **Большие файлы** (> 100 МБ) хешируются целиком, что может замедлить Obsidian. Планируется пропуск хеширования для больших файлов.
- **Обратные ссылки** из других заметок пока не собираются в заметке-каталоге. Задел на v3.
